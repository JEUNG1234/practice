데이터베이스에서의 다양한 유혀으이 관계

각 테이블의 데이터가 서로 어떻게 연결되고 상호작용하는지를 정의

--> 데이터의 일관성과 무결성을 유지하는 데 중요한 역할


1.일대일
한 테이블의 행 하나가 다른 테이블의 행 하나와 딱 하나씩 연결되는 관계입니다.

예를 들면, 사용자(User) 테이블과 사용자 프로필(UserProfile) 테이블이 있을 때,
한 명의 사용자는 하나의 프로필만 가질 수 있고, 그 프로필도 해당 사용자에게만 연결됩니다.

구현할 때는 한 테이블의 기본 키를 다른 테이블의 외래 키로 사용하고, **고유 제약조건(UNIQUE)**을 걸어서 1:1을 보장합니다.


2.일대다
한 테이블의 하나의 행이 다른 테이블의 여러 행과 연결되는 관계입니다.
즉, 한 명의 사용자는 여러 개의 게시글을 작성할 수 있지만,
하나의 게시글은 하나의 사용자(작성자)에게만 속합니다.

사용자 ↔ 게시글은 1:N 관계


이때 부서 테이블의 기본 키가 직원 테이블의 외래 키로 들어가게 됩니다.


3.다대다

사용자 ↔ 좋아요(Likes) ↔ 게시글
한 사용자는 여러 게시글에 좋아요를 누를 수 있고,

하나의 게시글도 여러 사용자에게 좋아요를 받을 수 있습니다.

👉 이때 사용자와 게시글 사이에는 다대다 관계가 발생합니다.

User
---------------------------------------
id | name   | liked_post_ids
---------------------------------------
1  | 홍길동 | 10, 13, 25
2  | 김영희 | 11, 25

| 문제        | 설명                                  |
| --------- | ----------------------------------- |
| 정규화 위반  | 한 셀에 여러 값을 넣음 → **1NF(제1정규형)** 위반   |
| 검색 불편  | 예를 들어 "25번 게시글에 좋아요 누른 사람은?" → LIKE '%25%' 문자열 검색을 해야 해서 성능도 나쁩니다.
| 수정 어려움 | 13번 게시글 좋아요 취소 → 문자열 조작             |
|  무결성 깨짐 | 이 방식은 Post 테이블의 ID와 외래키(FK) 관계를 만들 수 없습니다.
즉, 10, 13, 25가 실제 존재하는 게시글인지 DB가 알 수 없음.
| 🔄 조인 불가  | 게시글과 JOIN해서 정보 가져오기 힘듦              |

User
-----------------
id | name
1  | 홍길동

Post
-----------------
id | title
10 | 공지사항입니다

Like (중간 테이블)
------------------------
user_id | post_id
------------------------
1       | 10
1       | 13
1       | 25
2       | 11
2       | 25





서로 여러 개의 행이 서로 여러 개와 연결되는 복잡한 관계입니다.

예를 들어, 학생(Student)과 과목(Course) 관계를 생각해볼 수 있습니다.

한 학생은 여러 과목을 들을 수 있고,

한 과목도 여러 학생이 들을 수 있습니다.

관계형 데이터베이스에서는 이 다대다 관계를 직접 표현할 수 없기 때문에,
중간에 **연결 테이블(예: 수강신청 Enrollment)**을 하나 만들어서
두 개의 일대다 관계로 나누어 구현합니다.
